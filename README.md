# Housing Price Regression

Проект по построению регрессионной модели для оценки стоимости жилья на данных Boston Housing.

Основная цель проекта — реализовать регрессионный алгоритм с нуля и разобраться во внутренних механизмах обучения модели: градиентном спуске, масштабировании признаков, полиномиальных преобразованиях и оценке качества.

## Задача

В качестве входного признака используется:

- `RM` — среднее количество комнат в жилом объекте.

Целевая переменная:

- `MEDV` — медианная стоимость жилья.

Модель оценивает зависимость стоимости жилья от количества комнат.

## Что реализовано

В проекте реализованы:

- собственный класс `GDRegressor`;
- обучение методом градиентного спуска;
- стандартизация исходного признака;
- создание полиномиальных признаков;
- добавление bias;
- собственные функции RMSE и R²;
- подбор learning rate и количества итераций;
- разделение данных на train / validation / test;
- автоматические тесты;
- сравнение собственных метрик с реализациями `scikit-learn`.

## Полиномиальная регрессия

Для описания нелинейной зависимости исходный признак преобразуется в набор полиномиальных признаков.

При степени полинома 5 используются:

```text
x, x², x³, x⁴, x⁵
```

После создания полиномиальных признаков данные дополнительно стандартизируются.

Такой подход позволяет модели описывать более сложную зависимость, чем обычная линейная регрессия.

## Модель

В проекте используется собственный класс `GDRegressor`.

Модель самостоятельно выполняет:

- подготовку входных данных;
- стандартизацию;
- создание полиномиальных признаков;
- инициализацию весов;
- обучение методом градиентного спуска;
- построение прогнозов.

Для обучения модели не используется готовый класс `LinearRegression` из `scikit-learn`.

Основная логика реализована с помощью NumPy.

## Градиентный спуск

Веса модели обновляются итеративно по формуле:

```text
w = w - α · gradient
```

где:

- `w` — веса модели;
- `α` — learning rate;
- `gradient` — направление изменения функции ошибки.

На каждой итерации модель:

1. рассчитывает прогноз;
2. определяет ошибку;
3. рассчитывает градиент;
4. обновляет веса.

## Масштабирование данных

Перед обучением исходный признак стандартизируется.

Используется преобразование:

```text
z = (x - mean) / std
```

Стандартизация помогает градиентному спуску работать стабильнее и быстрее сходиться.

После создания полиномиальных признаков они также масштабируются.

В проекте дополнительно реализованы отдельные функции:

- `z_scaler`;
- `min_max`.

## Метрики качества

Для оценки модели используются две метрики.

### RMSE

Root Mean Squared Error показывает средний масштаб ошибки модели.

Чем меньше RMSE, тем ближе прогнозы к реальным значениям.

### R²

Коэффициент детерминации показывает, какую долю вариации целевой переменной объясняет модель.

Чем ближе R² к 1, тем лучше модель описывает данные.

Обе метрики реализованы вручную с помощью NumPy.

## Проверка собственных метрик

В `test_linreg.py` результаты собственных функций RMSE и R² сравниваются с готовыми реализациями из `scikit-learn`.

Используются:

```python
r2_score
root_mean_squared_error
```

Это позволяет проверить корректность собственных реализаций.

## Подбор параметров

Для модели перебираются разные комбинации:

- `alpha` — скорость обучения;
- `n_iter` — количество итераций.

Например:

```text
n_iter = 10000
alpha = 0.0001
```

или:

```text
n_iter = 5000
alpha = 0.001
```

Каждая комбинация проверяется на validation-выборке.

После этого выбираются параметры, которые дают максимальное значение R².

## Разделение данных

Данные разделяются на:

- обучающую выборку;
- validation-выборку;
- тестовую выборку.

Обучающая выборка используется для обучения модели.

Validation-выборка используется для подбора параметров.

Тестовая выборка используется для финальной оценки качества.

## Автоматические тесты

В проекте используется `unittest`.

Тест:

- загружает датасет;
- разделяет данные;
- подбирает параметры модели;
- обучает `GDRegressor`;
- получает прогнозы;
- рассчитывает RMSE и R²;
- сравнивает собственные метрики с `scikit-learn`.

Это позволяет автоматически проверять корректность модели после изменений в коде.
